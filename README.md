# 技术编辑选题推荐系统

面向技术编辑的选题推荐网页：编辑输入兴趣短文与六个主题的精确篇数配额，系统从 30 篇
本地文章中选出 6 篇组成阅读队列，在满足**主题精确配额**与**作者不重复**的前提下，
最大化加权相关度目标，并按每次两篇的节奏逐步揭示。

此外提供**断句建议（句末标点恢复）**：对句末标点丢失的 120～350 字中文稿件，从内置
30 篇文章正文的句末标点学习边界证据，结合 15～90 字句长做整篇断句，只在缺少标点的
字符间隙插入句号，证据不足的位置标记待复核而不强行加标点。

## 技术栈

- **FastAPI**：HTTP 接口与演示页面
- **scikit-learn**：字符 2~3 元 TF-IDF（`TfidfVectorizer(analyzer="char", ngram_range=(2,3))`）
  与余弦相似度
- **SQLite**（WAL 模式）：会话状态、异步重算任务、排除集、揭示票据的持久化
- 原生 HTML/CSS/JS 前端，无构建步骤

## 快速开始

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

已揭示前缀、兴趣、配额与排除集全部保留。

pip install -r requirements.txt

```

pip install -r requirements.txt pytest httpx

```

## 数据

`app/articles_data.py` 内置 30 篇中文文章，每篇含 `id / 标题 / 正文 / 单一主题 / 作者`：

- 6 个主题（人工智能、医疗健康、金融投资、旅游地理、美食烹饪、体育竞技），每主题 5 篇；
- 10 位作者，每人 3 篇且分布在 3 个不同主题；同一主题内 5 位作者互不相同。
  因此标准“每主题一篇”的队列天然满足作者不重复，而约束校验对任意配额仍然生效。

## 推荐算法

### 相关度

1. TF-IDF **只在 30 篇文章正文上 `fit`**，兴趣短文只做 `transform`，特征空间与
   IDF 权重完全由文章决定；
2. 特征为字符二元、三元组（已断言词表中不存在单字特征）；
3. 兴趣向量与每篇文章向量计算余弦相似度，截断到 `[0,1]` 作为相关度。

### 全局最优队列

求解器 `app/optimizer.py` 用逐主题组合枚举 + 分支定界求**精确全局最优**（非近似）：

- 六个主题按配额 `q_t` 枚举候选组合，强制作者互不重复；
- 给定入选文章集合，由重排不等式，按相关度降序放入权重降序的位置即最优排列；
- 目标函数：`Σ_{pos=1..6} (7 - pos) × 相关度`，位置权重为 6,5,4,3,2,1；
- 存在已揭示前缀时，前缀的位置与文章固定，只对剩余位置重新求全局最优；
- 分支定界的上界忽略跨主题作者冲突（只会高估），保证不剪掉真正的最优解；
- 单元测试中与全暴力枚举对拍，多次随机相关度/配额下结果完全一致；
- 平局按 `article_id` 确定性打破，重复求解结果稳定。

## 揭示规则与并发语义

- 每次点击揭示**两篇**，已揭示文章及其顺序**永久固定**并占用主题配额；
- 可随时修改兴趣、配额或排除/取消排除未揭示文章：未揭示位置按新条件重新全局优化，
  已揭示前缀保持不变；
- 无可行解时保留已揭示内容并停止揭示，接口返回明确原因（如某主题候选不足）；
- **同一条件（世代 generation）和同一进度点的“下一组”只推进一次**：
  进程内写锁串行化所有请求，并以 2 秒宽限窗口（可用环境变量 `REVEAL_CLAIM_TTL` 调整）
  识别并发批次，窗口内重复/并发请求复用首个请求的结果（`idempotent=true`）而不重复推进；
  窗口过后人工的下一次点击正常开启新一轮揭示；
- **慢重算可并发改条件，迟到结果不得揭示旧推荐**：每次条件变更生成新世代并把旧任务
  标记为 `stale`，后台 worker 写回前再次核对世代号，过期结果一律拒绝落库；
- 重算失败只把任务标记 `failed`，**不推进进度**，揭示接口会拒绝并提示；
- 所有状态落盘，**进程重启后已揭示前缀、世代、条件完整恢复**。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/status` | 当前状态、最新任务、完整推荐计划、文章清单 |
| `GET` | `/api/articles/{id}` | 单篇文章正文 |
| `PUT` | `/api/condition` | 修改兴趣和/或配额（请求体含 `interest`、`quotas`、可选 `compute_delay_ms`） |
| `POST` | `/api/exclusions` | 排除一篇未揭示文章（`article_id`） |
| `DELETE` | `/api/exclusions/{id}?compute_delay_ms=` | 取消排除 |
| `POST` | `/api/reveal` | 揭示下一组两篇 |
| `POST` | `/api/reset` | 重置演示数据 |
| `POST` | `/api/segment` | 断句建议：请求体 `{"text": "120~350 字稿件"}` |
| `GET` | `/api/segment/info` | 断句模型的语料校准信息（阈值、句长先验、约束常量） |

`compute_delay_ms` 用于在演示中人为制造慢重算（0~30000 毫秒），观察并发改条件与
过期保护行为。交互式文档见 `/docs`。

## 断句建议（句末标点恢复）

实现在 `app/segmenter.py`，**仅依赖 Python 标准库**，不引入新依赖。

### 输入与不可破坏的不变量

- 输入为 120～350 字（按非空白字符计数）的中文稿件，超出范围返回 `422`；
- **只在“两个内容字直接相邻、中间没有任何标点”的间隙插入句号**。逗号、顿号、
  冒号等句内标点所在间隙、引号/括号等中性标点间隙，以及原文已有的句末标点位置，
  一律不插入，**已有标点绝不重复**；
- **原有字符与顺序保持不变**：建议稿 = 原文 + 若干个“。”。删除新增句号后与原文
  逐字相等（测试中以无损还原断言固化）；
- 原文残留的句末标点作为**固定边界**保留并参与切分，不会被重复添加。

### 边界证据（从 30 篇正文学习，整篇校准阈值）

对每个可插入间隙（左字 `x`、右字 `y`）统计左单字、右单字、邻接二元组在“句末边界
间隙”与“全部间隙”上的计数，用 add-k 平滑的**条件对数几率增量**加权求和得到证据分：

```
score(x,y) = logit(prior)
           + 0.35·[logit P(boundary|x) − logit(prior)]
           + 0.45·[logit P(boundary|y) − logit(prior)]
           + 0.20·[logit P(boundary|xy) − logit(prior)]
```

- 模型只在 30 篇文章正文上统计（30 篇 × 5 句 = 150 个句末边界），输入稿件只做推断，
  **不参与拟合或调阈**；
- 可信阈值取语料真实边界证据分的 **25 分位**（整篇留出校准）：证据分 ≥ 阈值的边界
  标记为 `suggested`（建议插入句号），低于阈值的标记为 `review`（**待复核，建议稿中
  不插入句号**），从而贯彻“证据不足不强行加标点”。

### 句长结构先验与整篇动态规划

- 从语料学习句长均值（约 31 字）与每篇句数（恒为 5）；系统新切出的每个句段内容长度
  **硬约束在 15～90 字**；
- 原文残留句末标点把全文切成若干子区间，每个子区间枚举候选句数，做分层动态规划，
  目标为 `证据分加权和 + 句长高斯奖励 + 句数软约束`，选出整篇全局最优边界；
- 严格长度约束不可行时逐级放宽下限并把相应边界留作复核，保证任意合规输入都有输出。

### 返回结构

`POST /api/segment` 返回 `original_text`、`suggested_text`（仅高可信间隙插入句号）、
`segment_lengths`、校准 `threshold`、`stats` 与 `insertions` 列表；每个插入项含
`source_index`（原文插入点）、左右字符、`evidence`、`confidence`（suggested/review）
与该句段长度。前端据此同时展示建议稿、原文间隙对照（绿色“。”=建议、黄色“？”=待复核）
与插入位置明细表。

### 小语料下的能力边界（诚实说明）

30 篇、150 个边界的字面证据较稀疏，单字/二元组特征跨文章迁移有限：留一交叉验证下
间隙证据分 AUC 约 0.65，端到端恢复的 DP 边界（建议+复核合并）**精确 F1 约 0.36、
±2 字近命中率约 0.69**；其中真正过阈值、会在建议稿中插入句号的位置，**精度约
0.67**。因此系统刻意保守——结构先验负责定位候选边界，证据分只决定“建议插入”还是
“待复核”，宁可把不确定位置交给人工，也不在证据不足时强行加标点。这与“辅助校对、
人工把关”的定位一致；扩到更大、更多样的语料后字面证据的泛化能力会随之提升。
（以上数字由 `tests` 同口径的留一评测脚本测得，可复现。）

## 目录结构

```
app/
  articles_data.py   # 30 篇本地文章语料
  tfidf_model.py     # 仅文章拟合的字符 2~3 元 TF-IDF 单例
  optimizer.py       # 精确全局最优求解器（枚举 + 分支定界）
  segmenter.py       # 句末标点恢复：边界证据 + 句长结构 DP（纯标准库）
  database.py        # SQLite 持久化、世代、票据、串行写事务
  worker.py          # 后台异步重算线程与过期/失败处理
  main.py            # FastAPI 路由与生命周期
  static/            # 演示网页（index.html / app.js / style.css）
tests/               # 求解器对拍、TF-IDF 约束、断句模块/API、端到端 API 测试
Dockerfile, docker-compose.yml, requirements.txt
```

## 已知边界与取舍

- 数据规模固定为 30 篇/6 位置，精确枚举最坏情况单次求解约 0.2 毫秒；
  若文章量大幅增长，需要替换为整数规划或带剪枝的搜索，接口层无需改动。
- 演示采用单会话全局状态（对应两个浏览器窗口共享同一进度的设定）；
  多用户隔离需要再引入会话 ID 维度。
- 并发去重的宽限窗口是时间启发式（默认 2 秒）：足以覆盖线程调度、双击与网络重试，
  又远小于人工两次点击间隔；可通过环境变量调整。
